Set up DeepSeek

Only the account owner can create the key and decide whether to pay.

  1. Open the DeepSeek API platform, sign in and create an API key. A free chat account is not the same as API credit.
  2. Open Railway, choose the calving-log service, then Variables. Add the three values below. Never paste the secret into chat, GitHub or this application.
  3. Apply the variable changes and wait for deployment to succeed. Return here, refresh and select Test AI connection.
  4. A passed basic test proves that one fixed request worked, not the quality of database conversations. On Ask, select external AI and separately consent to selected demo-data results if you want record queries. Check the AI response label and source facts.

Control cost and privacy

  • AI_ENABLED=false in Railway turns external AI off; local Ask still works. Use true to enable it again.
  • AI_DAILY_REQUEST_LIMIT=200 limits requests across all users on this running server. Set 0 to stop paid requests. Failed requests and connection tests count too.
  • Daily counters use UTC and reset on a server restart. This is a request safeguard, not a guaranteed monetary spending cap. Check billing in your provider account.
  • Chat messages and recent conversation are sent only after AI opt-in. Separate demo-data consent allows a herd overview and selected query/label results. Not the entire database. Tools exclude credentials, staff identities, feedback and free-text clinical notes. Never type personal, farm-identifying or real clinical details.
  • One chat question may need several API calls to retrieve evidence and write a reply. Each upstream attempt counts against the request allowance. New chat clears in-memory context; no chat transcript is saved into the farm database.
  • If a key is wrong, credit runs out, a limit is reached, or the provider fails, Ask visibly falls back to local matching. Stored records and safety results stay unchanged.
